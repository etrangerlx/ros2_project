# ROS2 入门 21 讲 · 使用说明

本文档说明本工作空间（工作区路径 `<WS>`，即本项目根目录 `/root/ros2_ws/ros2_21_tutorials`）的**编译、运行、部署**方法。

- 系统环境：ROS 2 **Humble**，构建工具 `colcon`
- 工作空间布局：`build/`（构建产物）、`install/`（安装产物）、`log/`（构建日志），三者已由 `.gitignore` 忽略

> 下文所有命令中的 `<WS>` 请替换为实际路径。

---

## 1. 环境准备

每个新终端在执行编译或运行前，先加载系统 ROS 环境：

```bash
source /opt/ros/humble/setup.bash
```

进入工作空间根目录：

```bash
cd <WS>
```

## 3. 编译指令

### 3.1 全编译

```bash
# 标准全编译（Python + C++ + 接口）
colcon build

# 推荐：Python 包使用软链接安装，修改源码后无需重新编译
colcon build --symlink-install
```

常用增强参数：

```bash
colcon build --parallel-workers 4              # 限制并行编译任务数
colcon build --packages-skip learning_gazebo   # 跳过指定包
colcon build --event-handlers console_direct+  # 实时打印构建日志
```

### 3.2 部分编译

```bash
# 只编指定包（不会自动带上依赖，需保证依赖已编译/安装）
colcon build --packages-select learning_topic

# 连同其依赖一起编（推荐：编 learning_topic 会先编 learning_interface）
colcon build --packages-up-to learning_topic

# 编某包之后，把所有依赖它的包也一起重编
colcon build --packages-above learning_interface

# 一次选择多个包
colcon build --packages-select learning_topic learning_service learning_action
```

### 3.3 增量 / 强制重编 / 清理

```bash
# 强制 C++ 包重新执行 CMake configure
colcon build --cmake-force-configure

# 只清理单个包
rm -rf build/learning_topic install/learning_topic

# 彻底清理后全编译
rm -rf build install log && colcon build
```

> **提示**：修改了 `learning_interface` 的 `.msg/.srv/.action` 后，所有依赖它的包都必须重编，建议用 `colcon build --packages-above learning_interface`，或直接全编译。

## 4. 运行指令

运行前**必须**先加载本工作空间的环境（每个新终端都要执行）：

```bash
source <WS>/install/setup.bash
```

### 4.1 方式 A：`ros2 run` 运行单个节点

以下节点通常需要**两个终端**分别运行（发布/服务端 + 订阅/客户端）：

```bash
ros2 run learning_node        node_helloworld
ros2 run learning_node_cpp    node_helloworld_class

ros2 run learning_topic       topic_helloworld_pub
ros2 run learning_topic       topic_helloworld_sub

ros2 run learning_service     service_adder_server
ros2 run learning_service     service_adder_client

ros2 run learning_parameter   param_declare
ros2 run learning_action      action_move_server
ros2 run learning_qos         qos_helloworld_pub
ros2 run learning_cv          cv_bridge_test
```

### 4.2 方式 B：`ros2 launch` 一键启动

```bash
ros2 launch learning_launch simple.launch.py
ros2 launch learning_tf     turtle_following_demo.launch.py
ros2 launch learning_urdf   display.launch.py
ros2 launch learning_gazebo load_urdf_into_gazebo.launch.py
```

### 4.3 调试与验证命令

```bash
ros2 pkg list | grep learning          # 确认包已被识别
ros2 pkg executables learning_topic    # 查看某包可执行文件
ros2 node list                          # 当前节点
ros2 topic list                         # 当前话题
ros2 interface list | grep learning     # 自定义接口
```

## 5. 部署指令

ROS 2 的“部署”即**让安装产物被环境识别，可被其他程序调用**，核心是把工作空间加入环境（本项目未提供专门的部署脚本）。

### 5.1 环境部署

```bash
source /opt/ros/humble/setup.bash
source <WS>/install/setup.bash
```

写入 `~/.bashrc` 实现开机自动加载：

```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
echo "source <WS>/install/setup.bash" >> ~/.bashrc
```

### 5.2 依赖安装（换机器 / 新环境）

```bash
rosdep install --from-paths src --ignore-src -r -y
```

需注意的额外系统依赖：

- `learning_gazebo`、`learning_urdf`：`gazebo_ros`、`rviz2`、`xacro`、`robot_state_publisher`、`joint_state_publisher`
- `learning_cv`：`cv_bridge`、OpenCV

### 5.3 迁移部署

- **搬运安装产物**：将 `install/` 目录拷贝到目标机并 `source install/setup.bash`（要求目标机 ROS 版本一致，均为 Humble）。
- **搬运源码**：拷贝整个工作空间后在目标机重新 `colcon build`。

## 6. 常见问题

- **`Package 'xxx' not found`**：忘记 `source <WS>/install/setup.bash`，或该包尚未编译。
- **改了代码不生效**：Python 包用 `--symlink-install` 可免重编；C++ 包必须重新 `colcon build`。
- **编译报找不到自定义消息**：先编 `learning_interface`（用 `--packages-up-to` 或全编译）。
